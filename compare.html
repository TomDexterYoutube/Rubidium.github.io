Side by Side

Rubidium vs. Python vs. Rust vs. C

The same five tasks, written in all four languages, so you can see exactly where Rubidium's syntax sits — and where its memory model actually differs from the other three.

Hello, World
Rubidium
print("Hello, World!")
Python
print("Hello, World!")
Rust
fn main() {
    println!("Hello, World!");
}
C
#include <stdio.h>
int main() {
    printf("Hello, World!\n");
}
Variables & Mutation
Rubidium
let mut x: i32 = 10
x = 20
Python
x = 10
x = 20  # always reassignable
Rust
let mut x: i32 = 10;
x = 20;
C
int x = 10;
x = 20;

Rubidium and Rust both require an explicit mut to allow reassignment. Python has no concept of immutable variables at all. C allows reassignment unless the variable is const.

Loop 1 to 10
Rubidium
for i in range(1, 11) {
    print(i)
}
Python
for i in range(1, 11):
    print(i)
Rust
for i in 1..11 {
    println!("{}", i);
}
C
for (int i=1; i<11; i++) {
    printf("%d\n", i);
}

Rubidium's range(start, end) is exclusive of end, same as Python's and Rust's .. range — all three need 11 to cover 1 through 10.

Function
Rubidium
fn add(a: i32, b: i32) -> i32 {
    return a + b
}
Python
def add(a, b):
    return a + b
Rust
fn add(a: i32, b: i32) -> i32 {
    a + b
}
C
int add(int a, int b) {
    return a + b;
}
Class
Rubidium
class player() {
    let mut hp: i32 = 100
    fn hit(n: i32) {
        hp = hp - n
    }
}
Python
class Player:
    def __init__(self):
        self.hp = 100
    def hit(self, n):
        self.hp -= n
Rust
struct Player { hp: i32 }
impl Player {
    fn hit(&mut self, n: i32) {
        self.hp -= n;
    }
}
C
typedef struct {
    int hp;
} Player;

void hit(Player *p, int n) {
    p->hp -= n;
}

Rubidium has no self — fields are accessed directly by name inside a method, closer to how Python reads once you drop the explicit self. prefix.

Memory model — the real difference
LanguageHow memory is managed
RubidiumNo GC, no ownership/borrow checker. Every assignment is a full deep copy. Freed manually with .drop(). The one exception is link, which shares data until a plain reassignment breaks it.
PythonAutomatic garbage collection (reference counting + cycle detector). Assignment shares references by default — mutating one name can affect another pointing at the same object.
RustNo garbage collector. The compiler enforces ownership and borrowing rules at compile time — one owner at a time, borrows checked for validity, memory freed deterministically when the owner goes out of scope.
CFully manual — you call malloc()/free() yourself. No compiler-enforced safety net; forgetting to free or freeing twice is on you.

Where Rubidium sits: it avoids Python's hidden reference-sharing (deep copy makes aliasing bugs impossible by default) and avoids Rust's learning curve (no borrow checker to satisfy) — at the cost of copying data more often than a reference-based language would, and requiring the same manual discipline as C for actually freeing memory.
