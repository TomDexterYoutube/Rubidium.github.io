Chapter 00

Welcome to
The Rubidium Book

This book will teach you the Rubidium programming language from scratch — no prior systems programming experience required.

Rubidium is a high-performance, statically-typed compiled language designed to be approachable for beginners while scaling to real systems programming. It combines the clean, readable syntax of Python with an explicit, always-visible memory model — no hidden garbage collector, no ownership or borrow-checker rules to learn, just deep-copy-by-default and a manual .drop() when you're done with a value.

Who this book is for

This book assumes you can write basic programs in any language — loops, variables, functions. You don't need to know C, Rust, or anything low-level. If you've written Python, JavaScript, or similar, you'll feel right at home in the first few chapters.

What you'll learn

  • How Rubidium's type system and memory model work
  • All four collection types — list, index, dict, and dict+
  • Functions, classes, and isolated scopes
  • Manual memory management with .drop()
  • Real hardware threading with POSIX threads
  • File I/O, error handling, and the standard modules
  • How to use Xeon, Rubidium's build manager, to compile and run programs

How this book is structured

Chapters build on each other. Read them in order if you're new to the language. If you already know the basics, feel free to jump to any chapter from the sidebar. Every chapter contains working code examples you can copy and run immediately with Xeon.

💡

File extension: Rubidium source files use the .rub extension. The build tool is called Xeon. You'll set it up in the next chapter.

Chapter 01

Getting Started

Install Xeon, create your first project, and run your first Rubidium program.

Installing Xeon

Xeon is the official build manager for Rubidium. You use it to initialise projects, compile code, and run programs. Install it by cloning the repository and running the install script for your platform.

Linux / macOS
git clone https://github.com/TomDexterYoutube/Xeon-Rubidium
cd Xeon-Rubidium
./install.sh
Windows
git clone https://github.com/TomDexterYoutube/Xeon-Rubidium
cd Xeon-Rubidium
.\install.ps1

Creating a project

Make a new folder and run xeon init inside it. Xeon will create the src/ directory and a main.rub entry point for you.

terminal
mkdir hello-world
cd hello-world
xeon init

Your first program

Open src/main.rub and write the following:

src/main.rub Rubidium 
fn main() {
    print("Hello, Rubidium!")
}

Now compile and run it:

terminal
xeon run

You should see: Hello, Rubidium!

The execution model

Rubidium programs run in two phases — understanding this now saves confusion later.

  • Phase 1 — Top level: Everything written outside a function runs first, top to bottom. Variables are created, functions are defined (but not called).
  • Phase 2 — Main: After the top level finishes, the compiler automatically calls fn main().
src/main.rub Rubidium 
print("Phase 1 — this runs first")

fn main() {
    print("Phase 2 — this runs second")
}
💡

Tip: Use xeon build to compile without running, and xeon run to compile and execute in one step.

Chapter 02

Variables & Types

How to declare variables, annotate types, and work with Rubidium's type system.

Declaring variables

Use let to declare a variable. The type annotation goes after the variable name, separated by a colon. Type annotations are optional — Rubidium can infer the type from the value.

variables.rubRubidium
# With type annotation (colon before the type)
let name:  str  = "Rubidium"
let score: i32  = 100
let pi:    f64  = 3.14159
let alive: bool = True

# Without annotation — type is inferred
let x = 42         # inferred as i32 (or i64 depending on context)
let msg = "hello"  # inferred as str

Mutable variables

By default, variables cannot be reassigned. Add mut if you need to change the value later. Trying to reassign a non-mut variable is a compile error.

mut.rubRubidium
let mut count: i32 = 0
count = count + 1    # OK — count is mut

let name: str = "Alice"
name = "Bob"          # ERROR: name is not mutable

f3232-bit floatlet x: f32 = 3.14

Null

Null is a valid value for every type. It means the variable exists but currently holds no data.

null.rubRubidium
let x:    i32  = Null
let name: str  = Null
let flag: bool = Null

Type casting

Use the as keyword to cast between types.

casting.rubRubidium
let y:     i32 = 5
let large: i64 = y as i64
let f:     f64 = 100 as f64

Mathematics

math.rubRubidium

let b = 10 - 5    # 5   — subtraction
let c = 10 * 5    # 50  — multiplication
let d = 10 / 5    # 2   — division
let e = 2 ** 3   # 8   — power
let f = */16      # 4   — square root (prefix operator)

# Standard BODMAS precedence applies

let h = (1 + 2) * 3  # 9

Comparison & logic

logic.rubRubidium
# Comparison — returns bool
let check: bool = 10 > 5    # True
# == != > < >= <=

# Logic — and, or, not
let result: bool = True and not False   # True

Null behaves like negative infinity

Null is comparable, not just an empty placeholder. It is treated as smaller than every non-null value of its type — conceptually like negative infinity.

null-compare.rubRubidium
Null < 0          # True
Null < -999999   # True
Null == Null     # True

Integer overflow

Overflow does not crash the program. When a value would exceed a type's maximum or minimum, Rubidium clamps it to that limit, raises a runtime overflow error for that operation, and then keeps running.

  • Exceeding the maximum clamps to the maximum value.
  • Exceeding the minimum clamps to the minimum value.
  • The overflow error is reported once per operation — execution continues afterward with the clamped result already stored.
⚠️

Overflow is recoverable by design. Rubidium favors a program that keeps running over one that silently wraps or hard-crashes — you get a clamped value and a reported error, not undefined behavior.

⚠️

Gotcha: Calling let again on a name that already exists doesn't error and doesn't shadow — it drops the old variable and creates a brand-new one in its place (the Variable Overwrite Rule). And mut only controls whether you can reassign a value; it never lets you change a variable's type — that's still a compile error.

Check your understanding
What happens when you use let a second time on an existing name?
A: The old variable is dropped and a new one is created under the same name — it's not an error, and it's not the same as reassignment.
Is let mut x: i32 = 5; x = "hello" legal?
A: No. mut permits reassignment, not a type change — this is a compile-time type mismatch regardless of mutability.
Is Null < -999999 true or false?
A: True — Null behaves like negative infinity and is smaller than every non-null value.

Strings

Working with text in Rubidium — concatenation, interpolation, and string methods.

Basic strings

Strings are declared with double quotes and the str type.

strings.rubRubidium
let a: str = "Hello"
let b: str = "World"

# Concatenation with +
let c = a + " " + b       # "Hello World"

String interpolation

Use i"" (an interpolated string) to embed variable values directly inside text. Wrap the variable in {}.

interpolation.rubRubidium
let name:  str = "Alice"
let score: i32 = 42

print(i"Hello, {name}!")           # Hello, Alice!
print(i"Score: {score} points")    # Score: 42 points

String methods

Rubidium strings are zero-indexed and support a small set of built-in methods. Modifying a string in place (.set() / .insert() / .replace()) requires mut.

.set(index, value)Replaces the character at index. value must be a single character
.insert(index, value)Inserts value before index

.slice()Converts the string into a list of characters

let mut word: str = "banana"

print(text.slice())     # ["J", "e", "l", "l", "o", "!"]

User input

input() reads a line of text from the user and returns it as a str.

input.rubRubidium

⚠️

Gotcha: Methods that change a string in place — .set(), .insert(), .replace() — all require the string to be declared mut. Read-only methods like .char() and .len() work on non-mut strings just fine.

Check your understanding
Which of these needs mut: .len(), .char(i), or .replace(a,b)?
A: .replace() — it mutates the string. .len() and .char() only read.
True or false: .combine() is a string method.
A: False — .combine() belongs to list. Strings concatenate with +.
What does "Hello".slice() return?
A: A list of single-character strings: ["H","e","l","l","o"].

Chapter 04

Special Strings — SY & str+

Two string-flavored types with special powers: SY names things in code, and str+ spans multiple lines.

SY — using a string as a name

SY looks like a string but its value can be used as a variable or function name elsewhere in your code. Write the name with a single quote ' when you define it, and wrap it in parentheses () everywhere you use it.

sy.rubRubidium
let variable_name: SY = 'New variable'
let (variable_name): str = "Hello I'm a variable"

let function_name: SY = 'New function'

fn (function_name)() {
    print("I'm a new Function")
}
💡

Quotes matter here. Use 'single quotes' only when defining the SY value itself, and (parentheses) every time you reference that name as a variable or function.

str+ — multi-line strings

str+ behaves exactly like str, except it's wrapped in three double quotes on each side, which lets it span multiple lines.

strplus.rubRubidium
let my_str_plus: str+ = """
Hello
I'm a big string!
"""

A file's full contents from file.read() come back as a str+, since a whole file is typically multiple lines.

⚠️

Gotcha: The two quote styles for SY are easy to swap by accident: use 'single quotes' only when defining the SY value, and (parentheses) every time you reference that name afterward as a variable or function.

Check your understanding
When do you use 'quotes' vs (parens) with an SY value?
A: Single quotes when defining the SY value itself; parentheses every time you use that name as a variable or function elsewhere.
Does str+ require more than one line of content?
A: No — it always needs the triple-quote """ delimiters, but it can technically hold a single line too. Its purpose is just to allow multiple lines when you need them.

Chapter 05

Collections — List

An ordered, zero-indexed sequence that can hold mixed types.

Creating a list

Use square brackets. Lists require mut to be modified.

list.rubRubidium
let mut items: list = ["hello", 2.5, True]

Accessing items

Access by index using parentheses (zero-indexed).

list-access.rubRubidium
print(items(0))   # hello
print(items(1))   # 2.5
print(items(2))   # True

Mutating items

Use .set() to change an item in place.

list-mutate.rubRubidium
items(0).set("changed")
print(items(0))   # changed

Appending items

Use .add() on the list itself (empty parentheses) to append a new item.

list-add.rubRubidium
items().add("new item")

Deep copy rule

Assigning a list to a new variable creates a full deep copy. Modifying the copy does not affect the original.

deep-copy.rubRubidium
let mut a: list = [1, 2, 3]
let mut b = a

b(0).set(999)

print(a)   # [1, 2, 3]  — unchanged
print(b)   # [999, 2, 3]

Iterating over a list

Use a for loop. The loop variable is automatically freed when the loop ends.

list-iter.rubRubidium
let mut nums: list = [10, 20, 30]

for item in nums {
    print(item)
}
# prints 10, 20, 30

Combining a list into a string

.combine() joins every value in a list together into one string.

list-combine.rubRubidium
let words: list = ["Hello", " ", "World"]

print(words.combine())   # Hello World
⚠️

Gotcha: Appending uses empty parentheses on the list itself — items().add(x) — not an index. Writing items(0).add(x) instead targets element 0, not the list, and won't do what you expect.

Check your understanding
How do you append a new item to a list?
A: list().add(value) — empty parentheses on the list itself, not on an index.
If you assign let mut b = a where a is a list, and then mutate b, does a change too?
A: No — assignment is always a full deep copy in Rubidium. a and b are completely independent afterward.

Chapter 06

Collections — Index

A flat key→value map. Keys and values can be any type.

💡

Index vs Dict: An index maps one key to one value. A dict maps one key to a collection of values. They look similar but behave differently — see the next chapter for dict.

Creating an index

Uses square brackets with a colon : separating keys from values.

index.rubRubidium
let mut my_index: index = [
    "name":  "Rubidium",
    1:       "one",
    2.5:     "float key"
]

Accessing values

Access by key using parentheses.

index-access.rubRubidium
print(my_index("name"))   # Rubidium
print(my_index(1))         # one

Mutating a value

index-mutate.rubRubidium
my_index("name").set("updated")
print(my_index("name"))   # updated

Adding a new key

Use .add(key, value). This errors if the key already exists.

index-add.rubRubidium
my_index().add("new_key", 99)
⚠️

Note: Calling .add() with a key that already exists will produce a runtime error. Use .set() if you want to update an existing key.

⚠️

Gotcha: index().add(key, value) raises a runtime error if key already exists — it's strictly for new keys. Use .set() to update a key that's already there.

Check your understanding
What happens if you .add() a key that already exists in an index?
A: A runtime error. .add() is only for new keys; use .set() to update an existing one.
Can an index key be something other than a string?
A: Yes — keys can be any type, including numbers, as shown by 1: "one" and 2.5: "float key".

Chapter 07

Collections — Dict

A key→collection map. Each key holds multiple values.

Creating a dict

Uses curly braces with = separating keys from their value lists.

dict.rubRubidium
let mut my_dict: dict = {
    "scores" = [10, 20, 30],
    "names"  = ["alice", "bob"]
}

Accessing values

Access with dict(key, index) — you need both the key and the position within that key's collection.

dict-access.rubRubidium
print(my_dict("scores", 0))   # 10
print(my_dict("scores", 1))   # 20
print(my_dict("names",  0))   # alice

Mutating a value

dict-mutate.rubRubidium
my_dict("scores", 1).set(999)
print(my_dict("scores", 1))   # 999

Adding values

dict-add.rubRubidium
# Append to an existing key's collection
my_dict("scores").add(40)

# Add a brand-new top-level key (starts as Null)
my_dict().add("new_key")

Iterating over a dict

A for loop over a dict yields keys, not values. Use the key to access values.

dict-iter.rubRubidium
for key in my_dict {
    print(key)
    print(my_dict(key, 0))
}

Collection comparison

TypeSyntaxAccessUse when…
list[a, b, c]list(0)Ordered sequence of items
index["k": v]index("k")One key → one value
dict{"k" = [...]}dict("k", 0)One key → many values
⚠️

Gotcha: .add() means two different things on a dict depending on what you call it on: my_dict("scores").add(40) appends 40 to that key's collection, while my_dict().add("new_key") creates an entirely new top-level key (initialized to Null). Same method name, very different effect.

Check your understanding
What's the difference between my_dict("scores").add(40) and my_dict().add("new_key")?
A: The first appends 40 to the existing "scores" collection. The second creates a brand-new top-level key, starting out as Null.
True or false: a dict key holds exactly one value, like an index.
A: False — that's the whole distinction. An index key holds one value; a dict key holds a collection of values, accessed with dict(key, position).

Chapter 08

Collections — Dict+

dict+ is a dict that can nest inside itself to any depth — a key's value can be a plain list, or another dict+.

💡

dict vs dict+: a dict key always holds a flat list. A dict+ key can hold a list (a "leaf") or another dict+ block, nested as deep as you like.

Creating a dict+

dictplus.rubRubidium
let mut my_dictplus: dict+ = {
    1 = {
        "test" = [1, 2, 3, 4]
    }
}

Accessing nested values

Chain keys down through each level — dictplus(key1, key2, ...) keeps drilling until it reaches a list, then behaves like a normal dict from there.

dictplus-access.rubRubidium
print(my_dictplus(1, "test"))          # [1, 2, 3, 4]
print(my_dictplus(1, "test", 0))       # 1

Adding values and keys

Append to an existing leaf, add a new leaf key, or add a further nested dict+ — using a { } block instead of a list nests one level deeper.

dictplus-add.rubRubidium
# Append to the list at the end of the path
my_dictplus(1, "test").add("ten")

# Add a new leaf key (a list)
my_dictplus(1).add("other", [5, 6, 7])

# Add a further nested dict+ instead of a leaf
my_dictplus(1).add("deeper", { "layer2" = [8, 9] })

# New top-level key — created as an empty dict+
my_dictplus().add(2)

Keys follow the same naming rules

Just like index and dict: string keys need quotes ("test"), numbers and other types don't.

TypeSyntaxAccessUse when…
list[a, b, c]list(0)Ordered sequence of items
index["k": v]index("k")One key → one value
dict{"k" = [...]}dict("k", 0)One key → many values
dict+{"k" = {...}}dictplus("k","k2")Unlimited nested depth
⚠️

Gotcha: When you call .add() on a dict+ level, the shape of the second argument decides what you get: pass a list [...] to create a leaf, or a { } block to nest another level deeper. The method name never changes — only what you hand it.

Check your understanding
How do you tell dict+ to nest another level instead of creating a leaf?
A: Pass a { } block as the value instead of a list — e.g. .add("deeper", { "layer2" = [8,9] }).
What does my_dictplus().add(2) create?
A: A new top-level key 2, created as an empty dict+ — not Null the way a plain dict's new key would be.

Control Flow

Branching with if/else, looping with while and for.

if / else if / else

conditionals.rubRubidium
let x = 7

if x == 7 {
    print("lucky seven")
} else if x > 10 {
    print("big number")
} else {
    print("something else")
}

while loop

while.rubRubidium
let mut count = 0

while count < 5 {
    print(count)
    count = count + 1
}

for loop with range

range(start, end) — end is exclusive. The loop variable is automatically freed at the end of the block.

for-range.rubRubidium
for i in range(1, 10) {
    if i == 5 {
        break
    }
    print(i)
}
# prints 1 2 3 4

for loop over a list

for-list.rubRubidium
let mut items: list = [10, 20, 30]

for item in items {
    print(item)
}
💡

Loop variables are auto-freed. The loop variable (like i or item) is automatically dropped at the end of the loop block — you don't need to call .drop() on it.

⚠️

Gotcha: An else or else if must attach directly to the closing } of the previous branch — it's part of the same statement, not a new one. Putting a comment or blank line in a way that visually separates them doesn't break anything, but conceptually the chain is one continuous construct.

Putting it together

A small program combining variables, a for loop, %, and if / else if / else — classic FizzBuzz.

fizzbuzz.rubRubidium
fn main() {
    for n in range(1, 21) {
        if n % 15 == 0 {
            print("FizzBuzz")
        } else if n % 3 == 0 {
            print("Fizz")
        } else if n % 5 == 0 {
            print("Buzz")
        } else {
            print(n)
        }
    }
}

Note the range: range(1, 21) covers 1 through 20 because the end bound is exclusive.

Check your understanding
Is the loop variable in for i in range(1, 10) still accessible after the loop ends?
A: No — loop variables are automatically dropped the moment the loop ends, in for and while alike.
What's the value of range(1, 10)'s upper bound — is 10 included?
A: No — range(start, end) excludes end, so range(1, 10) yields 1 through 9.

Chapter 10

Functions

Defining reusable, isolated pieces of logic.

Basic function

functions.rubRubidium
fn greet() {
    print("Hello!")
}

greet()

Parameters and return types

Parameter types and the return type use the same colon annotation as variables. The return type goes after ->.

params.rubRubidium
fn add(a: i32, b: i32) -> i32 {
    return a + b
}

let result: i32 = add(10, 32)
print(result)   # 42

Functions without a return value

If a function doesn't return anything, just omit the -> and return type entirely.

no-return.rubRubidium
fn log(msg: str) {
    print(i"[LOG] {msg}")
}

log("Server started")

Isolated scope

Variables declared inside a function are not placed in the global pool. They only exist for the lifetime of that function call.

💡

Global pool vs function scope: Top-level variables and class fields live in the global pool — visible everywhere. Function-local variables are isolated and disappear when the function returns.

⚠️

Gotcha: Function parameters behave like local variables — they never enter the global pool, even though Rubidium is "global by default" everywhere else. They're dropped the instant the function returns.

Check your understanding
Do function parameters live in the global memory pool?
A: No — parameters are always local to that specific call, regardless of how everything else in Rubidium defaults to global.
Can you define two functions named add in the same scope with different parameter types?
A: No — Rubidium has no function overloading. Two functions with the same name in the same scope is a duplicate-symbol compile error.

Chapter 11

Memory Management

Rubidium has no garbage collector. You manage memory explicitly with .drop().

The global pool

All variables — except those inside functions, classes, or open() blocks — live in a shared global pool. Think of it as a whiteboard everyone can see and write on. Memory on this whiteboard is never freed automatically.

Freeing memory with .drop()

Call .drop() on any variable to immediately free its memory. After dropping, the variable no longer exists.

drop.rubRubidium
let val = 42
val.drop()
# val no longer exists after this point

let mut items: list = [1, 2, 3]
items.drop()
# All nested data inside items is freed too

Collections are freed recursively

When you .drop() a collection, every item inside it is also freed. This works for deeply nested structures too.

Automatic cleanup

There are two cases where Rubidium cleans up memory for you automatically — you don't need to call .drop():

  • Loop variables — the item or i in a for loop is freed at the end of each iteration.
  • open() file blocks — the file handle is closed and freed when the block exits.
🔴

No GC — memory won't free itself. If you create variables in a long-running loop and never drop them, your program's memory usage will grow. Get in the habit of calling .drop() when you're done with a value.

Local variables

Declare a variable with local to keep it out of the global pool entirely. Local variables exist only for their enclosing block — a function, class, loop, if, or while — and are dropped automatically when that scope ends.

local.rubRubidium
while True {
    let local num = 10
    break
}
# num is dropped automatically here — it never touched the global pool

The same rule applies inside functions, classes, for/while loops, and if blocks.

The Link Rule

Every normal assignment in Rubidium is a deep copy. link is the one exception: it lets two variables share the same underlying data instead of copying it — useful for passing a large value into a function without duplicating it.

link-fn.rubRubidium
fn stuff(val: Any) -> Any {
    val.add(7)
}

fn main() {
    let local large_list: list = ["Lots of Data"]
    stuff(link large_list)
}

link also works between two plain variables. Once linked, changing one changes the other — but reassigning either side with a plain = breaks the link and the two become independent again.

link-vars.rubRubidium
let a = 10
let b = link a
# a and b now share the same value

let x: list = [1, 2, 3]
let y = link x(2)   # link to a single element
⚠️

The only shared-reference mechanism in the language. Everywhere else, assignment is a full independent copy. Reach for link deliberately, and remember a reassignment (=) severs it.

⚠️

Gotcha: Dropping an element inside a collection — items(1).drop() — removes it and shifts everything else down. It does not leave a Null in its place, unlike .set()/.add(), which do fill or replace Nulls.

Check your understanding
After items(1).drop(), what's left at that position in the list?
A: Nothing — the rest of the list shifts down to fill the gap. No Null placeholder is inserted.
If you link two variables and then reassign one with a plain =, does the link survive?
A: No — a plain reassignment severs the link immediately; from that point on the two variables are fully independent.

Chapter 12

Classes

Self-contained object templates. No self keyword — class variables are accessed directly.

Defining a class

classes.rubRubidium
class player() {

    let mut health: i32  = 100
    let mut name:   str  = "unnamed"
    let mut scores: list = [0, 0, 0]

    fn greet() {
        print(i"Hi, I am {name}")
    }

    fn take_damage(amount: i32) {
        health = health - amount
    }
}

Creating an instance

instance.rubRubidium
let mut p = player()

print(p.health)   # 100

Mutating fields

For non-collection fields, use = directly. For collection fields, use .set(). The instance must be declared with mut.

mutating.rubRubidium
# Non-collection field
p.health = 80
p.name   = "Alice"

# Collection field — use .set() from outside the class
p.scores(0).set(99)

# Append to a collection field
p.scores().add(50)

# Call a method
p.greet()
p.take_damage(10)

Inside methods — no instance prefix

Inside a class method, you access fields directly by name — no self. or instance prefix needed.

inside-method.rubRubidium
fn take_damage(amount: i32) {
    health = health - amount   # direct field access, no self
}

Immutable fields

Fields declared without mut can never be changed from outside the class.

locked.rubRubidium
class locked() {
    let value: i32 = 42   # not mut — cannot be changed
}

let mut obj = locked()
obj.value = 99   # ERROR: value is not declared mut
⚠️

Gotcha: Mutating a class field from outside requires two permissions at once: the instance itself must be declared mut, and the specific field must be declared mut inside the class. Missing either one is a compile error.

Putting it together

A tiny inventory system combining a class, a mut list field, and methods — plus a look at the deep-copy rule in action.

inventory.rubRubidium
class inventory() {

    let mut items: list = []

    fn add_item(name: str) {
        items().add(name)
    }

    fn count() -> i32 {
        return items.len()
    }
}

fn main() {
    let mut bag_a = inventory()
    bag_a.add_item("Sword")
    bag_a.add_item("Shield")

    # Assigning to bag_b makes a full, independent copy
    let mut bag_b = bag_a
    bag_b.add_item("Potion")

    print(bag_a.count())   # 2 — unaffected by bag_b
    print(bag_b.count())   # 3
}

Because class instances follow the same deep-copy rule as everything else, bag_b starts as a full independent copy of bag_a — adding to one never touches the other.

Check your understanding
If an instance is mut but a field inside the class wasn't declared mut, can you change that field from outside?
A: No — both gates have to be open: the instance needs mut, and so does the individual field.
Do class instances live in the shared global memory pool the way top-level variables do?
A: No — each instance owns its own separate data. Assigning one instance to another still does a full deep copy, same as collections.

Chapter 13

Error Handling

Catch runtime errors gracefully with try / error.

try / error

Wrap risky code in a try block. If anything inside it fails at runtime, execution jumps to the error block. The special variable error holds the error message as a string.

try.rubRubidium
try {

    let bad: i32 = 10 / 0

} error {

    print("Error: " + error)
}

try with file operations

try-file.rubRubidium
try {

    open("missing.txt") as file {
        print(file.read())
    }

} error {

    print("File error: " + error)
}
💡

Always wrap file I/O in try/error — files can fail to open for many reasons (missing, wrong permissions, network drives). It's good practice to handle those cases explicitly.

Compile-time vs. runtime errors

Rubidium catches as much as possible before your program ever runs. try / error only catches the runtime kind.

Compile ErrorsRuntime Errors
Unknown variable, function, class, or namespaceDivide by zero
Type mismatchInvalid index / missing collection key
Mutability violation (editing a non-mut value)Accessing dropped memory
Duplicate symbol definitionInvalid file operations
Invalid assignment targetInvalid FFI calls
💡

Compile errors stop the program from building at all. Runtime errors happen mid-execution and are exactly what try / error is for.

⚠️

Gotcha: try / error only catches runtime errors. A type mismatch, a mutability violation, or an unknown symbol is a compile-time error — the program won't even finish building, so try never gets a chance to run.

Check your understanding
Will try { let x: i32 = "hello" } error { ... } catch that mismatch?
A: No — that's a compile error. The program fails to build entirely, before try can do anything.
What type is the special error variable inside an error block?
A: A string — specifically str+, since error messages can span multiple lines.

Chapter 14

Files

Reading, writing, and managing files on disk.

Opening a file

Use open("path") as file { }. The file handle is automatically closed when the block ends. Variables created inside persist; the file handle does not.

files.rubRubidium
open("data.txt") as file {

    file.write("Hello")        # overwrite entire file
    file.add(" World")          # add to end of file

    let data = file.read()      # read entire file
    print(data)

    let line = file.readln(3)  # read line 3
    file.writeln(2, "Updated") # overwrite line 2
}

Iterating over lines

file-iter.rubRubidium
open("data.txt") as file {
    for line in file {
        print(line)
    }
}

File utilities

These are used outside of open blocks.

file-utils.rubRubidium
file.exists("data.txt")               # → bool
file.new("data.txt")                   # create new file
file.delete("old.txt")                 # delete file
file.rename("old.txt", "new.txt")     # rename file
file.copy("save.txt", "backup.txt")   # copy file
file.list("data/")                        # list a directory, like ls
💡

If a file doesn't exist, open() raises an error, creates the file, then continues — wrap it in try / error if you need to handle that explicitly (see the previous chapter).

⚠️

Gotcha: Variables you create inside an open() as file { } block survive after the block ends — but the file handle itself does not. Calling file.read() after the block has closed will fail.

Check your understanding
After an open() block ends, can you still call methods on that file handle?
A: No — the handle is automatically closed and dropped when the block exits. Only variables you assigned inside the block persist.
What happens if you open() a path that doesn't exist yet?
A: It raises an error, creates the file, and then continues — wrap it in try / error if you need to branch on that explicitly.

Chapter 15

Threading

Run code in parallel using real POSIX hardware threads.

Enabling the module

threads.rubRubidium
use thread

Spawning threads

thread(fn(), id) runs a function asynchronously on a hardware thread. The ID is an integer you choose — reuse an ID only after that thread has finished.

spawn.rubRubidium
use thread

fn task_a() {
    print("Task A running")
}

fn task_b() {
    print("Task B running")
}

fn run() {
    thread(task_a(), 1)
    thread(task_b(), 2)

    # Block until both threads are done
    thread.wait(1, 2)

    print("Both done")
}

Checking if a thread is running

check-thread.rubRubidium
let still: bool = thread.running(1)
print(i"Thread 1 still running: {still}")
⚠️

Gotcha: Two threads can call the exact same function, but each gets its own private copy of that function's parameters and locals. The only way two threads can actually race each other is through a shared global variable.

Putting it together

Two hardware threads each summing their own batch of random numbers, timed with a single timer — combining thread, random, and time in one program.

parallel_sum.rubRubidium
use thread
use random
use time

let mut total_a: i32 = 0
let mut total_b: i32 = 0

fn worker_a() {
    let local mut i: i32 = 0
    while i < 1000 {
        total_a = total_a + random(0, 100, i32)
        i = i + 1
    }
}

fn worker_b() {
    let local mut i: i32 = 0
    while i < 1000 {
        total_b = total_b + random(0, 100, i32)
        i = i + 1
    }
}

fn main() {
    time.timer_start(1)

    thread(worker_a(), 1)
    thread(worker_b(), 2)
    thread.wait(1, 2)

    let elapsed = time.timer_read(1)
    print(i"Combined total: {total_a + total_b}")
    print(i"Took {elapsed}s")
}

total_a and total_b are globals, so both threads' writes are visible from main() once thread.wait() returns — each thread only had to keep its own loop counter i private.

Check your understanding
If two threads call the same function, do they share its local variables?
A: No — parameters and locals are always private per-thread. Only global variables are shared.
Does Rubidium protect against race conditions on a shared global?
A: No — there's no automatic protection. If multiple threads write to the same global simultaneously, the result is undefined.

Random

Generate random numbers and shuffle collections.

random.rubRubidium
use random

# Random number — random(min, max, type)
let r_int: i32 = random(0, 10, i32)

let mut items: list = [1, 2, 3, 4, 5]

Check your understanding
What are the three arguments to random(min, max, type)?
A: The minimum value, the maximum value, and the numeric type you want back (e.g. i32, f32).
Can random.choice() be used on a dict, or only a list?
A: Both, plus index — and you can also call it on one specific key's collection, like random.choice(my_dict("scores")).

Chapter 17

Time

Pause execution and measure elapsed time with named timers.

time.rubRubidium
use time

# Pause execution for N seconds
time.wait(5)

# Named timers — identified by integer IDs
# Multiple timers can run simultaneously

time.timer_start(1)          # starts timer 1, returns f32
time.timer_start(2, f64)     # starts timer 2, returns f64

time.timer_pause(1)          # pauses timer 1 (keeps elapsed time)
time.timer_stop(1)           # stops and resets timer 1

let elapsed = time.timer_read(1)   # seconds.fractional seconds
print(i"Elapsed: {elapsed}s")
⚠️

Gotcha: Timer IDs and thread IDs are both "just an integer you choose" — it's easy to accidentally reuse the same ID for both and confuse yourself. Keep separate numbering conventions for the two if you're using both in one program.

Check your understanding
What's the difference between time.timer_pause() and time.timer_stop()?
A: timer_pause() freezes the timer but keeps its elapsed time so it can resume; timer_stop() resets it back to zero.
What type does time.timer_start(1) return if you don't specify one?
A: f32 — pass a type explicitly, e.g. time.timer_start(1, f64), if you need more precision.

OS & FFI

Run shell commands and call into native libraries.

OS module

os.rubRubidium
use os

# Start a hidden terminal session (Linux=bash, Windows=cmd/powershell)
os.start(1)

# Run a command in that session
os.run(1, "ls -a")

# Capture output
let output = os.run(1, "echo hello")

# Auto-respond to prompts
let result = os.run(1, "sudo apt update", "y")

# Free the session
os(1).drop()

FFI — Foreign Function Interface

Load compiled shared libraries and call C, C++, C#, or Rust functions directly from Rubidium.

ffi.rubRubidium
use FFI

# Load a shared library (.so on Linux, .dll on Windows)
let c_lib = FFI("libs/mylib.so")

# Bind a function from the library
# fn [handle] [symbol](params) -> return_type as [rubidium_name]
fn c_lib my_c_function(msg: str) -> i32 as my_function

# Call using the Rubidium-side name
my_function("hello from Rubidium")

Renaming foreign symbols

External libraries often expose ugly, mangled, or version-suffixed names. The as clause lets you expose a clean Rubidium-facing name instead — the binding above already does this (my_c_function → my_function). Foreign functions can also be wrapped in an ordinary fn to add validation or compose several calls together.

⚠️

Gotcha: The third argument to os.run() is sent the instant the command asks for input — if the command never prompts, it's simply unused; if it prompts more than once, only the first prompt receives it.

Check your understanding
What does the third argument to os.run(id, cmd, input) do?
A: It auto-supplies that text the moment the running command requests input — useful for things like confirmation prompts.
When you bind fn lib_handle symbol_name(...) -> type as new_name, which name do you call it with?
A: The alias — new_name. That's the whole point of the as clause: exposing a clean name to your Rubidium code regardless of what the library calls it internally.

How to enable built-in modules and bring in external files.

use — built-in modules

use enables a compiler-provided module. A module that isn't declared with use cannot be accessed — even if you know its functions exist.

import loads another .rub file from the same folder as your source file. The imported file's top-level code runs, and its functions become available.

import math_tools   # loads math_tools.rub from the same folder

If you import a file but forget use thread, can that file's code use threading?
A: No — use is required independently for every built-in module, no matter what you've imported.
Does aliasing an import with as remove access to the original namespace?
A: No — both the alias and the original namespace stay valid at the same time; aliasing only adds a shorter name.
