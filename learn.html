Chapter 01

Getting Started

Install Xeon, create your first project, and run your first Rubidium program.

Installing Xeon

Xeon is the official build manager for Rubidium. You use it to initialise projects, compile code, and run programs. Install it by cloning the repository and running the install script for your pl[...]

Linux / macOS
git clone https://github.com/TomDexterYoutube/Xeon-Rubidium
cd Xeon-Rubidium
./install.sh
Windows
git clone https://github.com/TomDexterYoutube/Xeon-Rubidium
cd Xeon-Rubidium
install.bat

Creating a project

Make a new folder and run xeon init inside it. Xeon will create the src/ directory and a main.rub entry point for you.

terminal
mkdir hello-world
cd hello-world
xeon init

Your first program

Open src/main.rub and write the following:

src/main.rub Rubidium 
fn main() {
    print("Hello, Rubidium!")
}

Now compile and run it:

terminal
xeon run

You should see: Hello, Rubidium!

The execution model

Rubidium programs run in two phases — understanding this now saves confusion later.

  • Phase 1 — Top level: Everything written outside a function runs first, top to bottom. Variables are created, functions are defined (but not called).
  • Phase 2 — Main: After the top level finishes, the compiler automatically calls fn main().
src/main.rub Rubidium 
print("Phase 1 — this runs first")

fn main() {
    print("Phase 2 — this runs second")
}
💡

Tip: Use xeon build to compile without running, and xeon run to compile and execute in one step.

Chapter 02

Variables & Types

How to declare variables, annotate types, and work with Rubidium's type system.

Declaring variables

Use let to declare a variable. The type annotation goes after the variable name, separated by a colon. Type annotations are optional — Rubidium can infer the type from the value.

variables.rubRubidium
# With type annotation (colon before the type)
let name:  str  = "Rubidium"
let score: i32  = 100
let pi:    f64  = 3.14159
let alive: bool = True

# Without annotation — type is inferred
let x = 42         # inferred as i32 (or i64 depending on context)
let msg = "hello"  # inferred as str

Mutable variables

By default, variables cannot be reassigned. Add mut if you need to change the value later. Trying to reassign a non-mut variable is a compile error.

mut.rubRubidium
let mut count: i32 = 0
count = count + 1    # OK — count is mut

let name: str = "Alice"
name = "Bob"          # ERROR: name is not mutable

Null

Null is a valid value for every type. It means the variable exists but currently holds no data.

null.rubRubidium
let x:    i32  = Null
let name: str  = Null
let flag: bool = Null

Type casting

Use the as keyword to cast between types.

casting.rubRubidium
let y:     i32 = 5
let large: i64 = y as i64
let f:     f64 = 100 as f64

Chapter 03

Strings

Working with text in Rubidium — concatenation, interpolation, and string methods.

Basic strings

Strings are declared with double quotes and the str type.

strings.rubRubidium
let a: str = "Hello"
let b: str = "World"

# Concatenation with + or .combine()
let c = a + " " + b       # "Hello World"
let d = a.combine(b)      # "HelloWorld"

String interpolation

Use i"" (an interpolated string) to embed variable values directly inside text. Wrap the variable in {}.

interpolation.rubRubidium
let name:  str = "Alice"
let score: i32 = 42

print(i"Hello, {name}!")           # Hello, Alice!
print(i"Score: {score} points")    # Score: 42 points

String methods

string-methods.rubRubidium
let a: str = "Hello"

# Length — returns i64
let length: i64  = a.len()
# Contains — returns bool
let found:  bool = a.has("ell")   # True

Type conversion

Convert between strings and numbers with .to().

conversion.rubRubidium
# String → number
let num_str: str = "123"
let i: i32 = num_str.to(i32)
let f: f64 = num_str.to(f64)

# Number → string
let n: i32 = 42
let s: str = n.to(str)

User input

input() reads a line of text from the user and returns it as a str.

input.rubRubidium
let user: str = input("Enter your name: ")
print(i"Hello, {user}!")

Chapter 04

Collections — List

An ordered, zero-indexed sequence that can hold mixed types.

Creating a list

Use square brackets. Lists require mut to be modified.

list.rubRubidium
let mut items: list = ["hello", 2.5, True]

Accessing items

Access by index using parentheses (zero-indexed).

list-access.rubRubidium
print(items(0))   # hello
print(items(1))   # 2.5
print(items(2))   # True

Mutating items

Use .set() to change an item in place.

list-mutate.rubRubidium
items(0).set("changed")
print(items(0))   # changed

Appending items

Use .add() on the list itself (empty parentheses) to append a new item.

list-add.rubRubidium
items().add("new item")

Deep copy rule

Assigning a list to a new variable creates a full deep copy. Modifying the copy does not affect the original.

deep-copy.rubRubidium
let mut a: list = [1, 2, 3]
let mut b = a

b(0).set(999)

print(a)   # [1, 2, 3]  — unchanged
print(b)   # [999, 2, 3]

Iterating over a list

Use a for loop. The loop variable is automatically freed when the loop ends.

list-iter.rubRubidium
let mut nums: list = [10, 20, 30]

for item in nums {
    print(item)
}
# prints 10, 20, 30

Chapter 05

Collections — Index

A flat key→value map. Keys and values can be any type.

💡

Index vs Dict: An index maps one key to one value. A dict maps one key to a collection of values. They look similar but behave differently.

Creating an index

Uses square brackets with a colon : separating keys from values.

index.rubRubidium
let mut my_index: index = [
    "name":  "Rubidium",
    1:       "one",
    2.5:     "float key"
]

Accessing values

Access by key using parentheses.

index-access.rubRubidium
print(my_index("name"))   # Rubidium
print(my_index(1))         # one

Mutating a value

index-mutate.rubRubidium
my_index("name").set("updated")
print(my_index("name"))   # updated

Adding a new key

Use .add(key, value). This errors if the key already exists.

index-add.rubRubidium
my_index().add("new_key", 99)
⚠️

Note: Calling .add() with a key that already exists will produce a runtime error. Use .set() if you want to update an existing key.

Chapter 06

Collections — Dict

A key→collection map. Each key holds multiple values.

Creating a dict

Uses curly braces with = separating keys from their value lists.

dict.rubRubidium
let mut my_dict: dict = {
    "scores" = [10, 20, 30],
    "names"  = ["alice", "bob"]
}

Accessing values

Access with dict(key, index) — you need both the key and the position within that key's collection.

dict-access.rubRubidium
print(my_dict("scores", 0))   # 10
print(my_dict("scores", 1))   # 20
print(my_dict("names",  0))   # alice

Mutating a value

dict-mutate.rubRubidium
my_dict("scores", 1).set(999)
print(my_dict("scores", 1))   # 999

Adding values

dict-add.rubRubidium
# Append to an existing key's collection
my_dict("scores").add(40)

# Add a brand-new top-level key (starts as Null)
my_dict().add("new_key")

Iterating over a dict

A for loop over a dict yields keys, not values. Use the key to access values.

dict-iter.rubRubidium
for key in my_dict {
    print(key)
    print(my_dict(key, 0))
}

Collection comparison

TypeSyntaxAccessUse when…
list[a, b, c]list(0)Ordered sequence of items
index["k": v]index("k")One key → one value
dict{"k" = [...]}dict("k", 0)One key → many values

Chapter 07

Control Flow

Branching with if/else, looping with while and for.

if / else if / else

conditionals.rubRubidium
let x = 7

if x == 7 {
    print("lucky seven")
} else if x > 10 {
    print("big number")
} else {
    print("something else")
}

while loop

while.rubRubidium
let mut count = 0

while count < 5 {
    print(count)
    count = count + 1
}

for loop with range

range(start, end) — end is exclusive. The loop variable is automatically freed at the end of the block.

for-range.rubRubidium
for i in range(1, 10) {
    if i == 5 {
        break
    }
    print(i)
}
# prints 1 2 3 4

for loop over a list

for-list.rubRubidium
let mut items: list = [10, 20, 30]

for item in items {
    print(item)
}
💡

Loop variables are auto-freed. The loop variable (like i or item) is automatically dropped at the end of the loop block — you don't need to call .drop().

Chapter 08

Functions

Defining reusable, isolated pieces of logic.

Basic function

functions.rubRubidium
fn greet() {
    print("Hello!")
}

greet()

Parameters and return types

Parameter types and the return type use the same colon annotation as variables. The return type goes after ->.

params.rubRubidium
fn add(a: i32, b: i32) -> i32 {
    return a + b
}

let result: i32 = add(10, 32)
print(result)   # 42

Functions without a return value

If a function doesn't return anything, just omit the -> and return type entirely.

no-return.rubRubidium
fn log(msg: str) {
    print(i"[LOG] {msg}")
}

log("Server started")

Isolated scope

Variables declared inside a function are not placed in the global pool. They only exist for the lifetime of that function call.

💡

Global pool vs function scope: Top-level variables and class fields live in the global pool — visible everywhere. Function-local variables are isolated and disappear when the function returns.

Chapter 09

Memory Management

Rubidium has no garbage collector. You manage memory explicitly with .drop().

The global pool

All variables — except those inside functions, classes, or open() blocks — live in a shared global pool. Think of it as a whiteboard everyone can see and write on. Memory on this pool persists until you explicitly free it.

Freeing memory with .drop()

Call .drop() on any variable to immediately free its memory. After dropping, the variable no longer exists.

drop.rubRubidium
let val = 42
val.drop()
# val no longer exists after this point
