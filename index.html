Core Philosophy

Built on Four Pillars

PY

Python Readability

No semicolons, brace-delimited blocks, and familiar control flow. Code reads like intention, not punctuation.

RS

Rust-Style Safety

Mutable variables require explicit mut. Type mismatches are caught at compile time before code ever runs.

LLVM

LLVM Performance

Compiles directly to highly optimised native machine code via LLVM — execution speeds comparable to C or Rust.

§

Deep Memory Control

Call .drop() to recursively free all nested allocations in a single operation, eliminating leak paths.

Quick Reference

Language at a Glance

No Semicolons

Statements are newline-terminated. Clean, prose-like code structure throughout.

1-Based Indexing

All lists and dicts start at index 1, not 0.

println() Overwrites

println() replaces the current line rather than appending a newline.

No Self in Classes

Inside a class, variables are referenced directly by name — no self.

use vs import

use loads built-in modules. import loads external .rub files.

File I/O Built In

file_write() and file_read() require no import.

Collection type notes

list

Ordered, mixed-type array. Heap-managed with boxed memory. Starts at index 1.

Key–value store. Keys may be strings, integers, or floats — mixed types allowed.

dict

Named nested collections with multi-argument access for reaching inner elements.

Memory Management

Drop Deeply, Drop Cleanly

Rubidium uses explicit memory management through the .drop() method. Calling it on any variable frees it completely — the identifier ceases to exist after the call.

∅

Scalar Drop

Calling .drop() on a primitive frees its memory and removes the variable from scope entirely.

⟳

Recursive Collection Drop

For collections and strings, .drop() recursively frees every nested box, array key, and allocated value in a single call — no manual traversal needed.

✓

Leak Prevention

Deep drops on list, index, and dict types eliminate the leak paths that arise from manual pointer traversal.

⊞

Compiler-Managed Boxing

Collections dynamically manage boxed memory under the hood — the compiler handles allocation automatically while you control the lifecycle.

# Scalar drop let x: i32 = 42 x.drop() # x no longer exists # Deep list drop let nums: list = [1, 2, 3] nums.drop() # frees list + all values # Deep dict drop let data: dict = { "items" = [1, 2, 3], "meta" = ["ok", 99] } data.drop() # frees: dict + both lists # + every value inside them # String drop let msg: str = "hello" msg.drop() # heap string freed

Concurrency

Real Hardware Threads

Rubidium uses actual POSIX threads via the thread module. Functions are dispatched by numeric ID and awaited with thread.wait() before execution continues past the barrier.

MAIN
fn main() — dispatch threads
THREAD 1
task1() — id: 1
THREAD 2
task2() — id: 2
WAIT
thread.wait(1, 2) — blocks until both return
CONTINUE
execution resumes past the barrier
use thread fn task1() { print("Task 1 Finished") } fn task2() { print("Task 2 Finished") } fn run_threads() { thread(task1(), 1) # dispatch with id 1 thread(task2(), 2) # dispatch with id 2 thread.wait(1, 2) # wait for both to finish } fn main() { run_threads() print("All tasks done") }

Modules

use and import

Rubidium separates built-in compiler directives from user file imports with two distinct keywords.

use

Loads compiler-provided built-in modules such as thread.

use thread

import

Loads and compiles your own external .rub files into the current project.

import math_tools

Xeon Build Manager

One Tool. Every Platform.

Xeon is the official build manager for Rubidium. It initialises projects, compiles from src/main.rub, and outputs runnable binaries to build/. Works on Windows, Linux, and macOS.

xeon init Creates a new project in the current directory — generates a src/ folder and a boilerplate main.rub entry point.
xeon build Compiles your project starting from src/main.rub. Places the resulting binary inside the build/ directory.
xeon run Builds the project and immediately executes the resulting binary — compile and run in one step.

To update the compiler, replace the files inside ~/.xeon with the newer version. No reinstall needed.

Terminal — Example Workflow
$ mkdir my_app && cd my_app
$ xeon init
  → created src/main.rub
  → project ready

# edit src/main.rub

$ xeon build
  → compiled → build/

$ xeon run
  → building...
  Welcome to Rubidium!

Installation

Get Started in Three Steps

The installer automatically detects and installs required dependencies including Python 3 and Clang. The xeon command is added to your system path automatically. Supports Windows, Linux, and macOS.

Windows
01Download Rubidium from GitHub and rename the extracted folder to exactly Rubidium — the name must be exact
02Download Xeon and place the Rubidium folder inside it at rubidium/
03Run install.bat to install Xeon globally and configure your path
macOS
01Download Rubidium and Xeon from GitHub
02Place the Rubidium compiler files inside the Xeon directory at rubidium/
03Run bash install.sh — configures ~/.xeon and adds xeon to your path
Linux
01Download Rubidium and Xeon from GitHub
02Place the Rubidium compiler files inside the Xeon directory at rubidium/
03Run bash install.sh — auto-installs Python 3 and Clang, sets up path
→ Updating: Replace the files inside ~/.xeon with the newer version at any time — no reinstall required.
→ Windows note: The extracted folder must be renamed to exactly Rubidium before placing it in the Xeon directory.
