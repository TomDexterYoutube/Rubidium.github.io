RUBIDIUM

Python Clarity · Rust Discipline · LLVM Speed

A statically typed, memory-safe compiled language. Clean, readable syntax meets low-level control — compiled to native machine code via LLVM for performance comparable to C or Rust.

Core Philosophy

Built on Four Pillars

PY

Python Readability

No semicolons, brace-delimited blocks, and familiar control flow. Code reads like intention, not punctuation.

RS

Rust-Style Safety

Mutable variables require explicit mut. Type mismatches are caught at compile time before code ever runs.

LLVM

LLVM Performance

Rubidium compiles directly to highly optimised native machine code via LLVM — execution speeds comparable to C or Rust.

§

Deep Memory Control

Call .drop() to recursively free all nested allocations in a single operation, eliminating leak paths.

Type System

Every Bit Accounted For

Fine-grained numeric types from 8-bit to 256-bit, with full compile-time enforcement. The compiler rejects any assignment that would mismatch a declared type. Type casting uses the as keyword.

Integer Types

i8 i16 i32 i64 i128 i256

Float Types

f4 f8 f16 f32 f64 f128 f256

Primitive Types

str bool

Collection Types

list index dict
# Booleans use capitalised literals
let active: bool = True

# Type casting with `as`
let big: i64 = some_i32 as i64
let precise: f64 = 100 as f64

# Type mismatch → compile-time error
# let val: i32 = "hello" ← rejected

Syntax

Familiar, Not Fragile

# Immutable by default — type inferred

# Mutable requires `mut` keyword

# Explicit types

# Variables are global except across
# files and within class scope
# Parameters typed, return type after `->`

    let result = a + b
    return result
}

let total = add(2, 3)

# Compiler requires main() as entry point

}
# Classes are self-contained units
# No `self` — variables referenced directly
class Counter() {
    let mut value: i32 = 0

    fn increment() {
        value = value + 1
    }

    fn get() -> i32 {
        return value
    }
}

fn main() {
    let mut c = Counter()
    c.increment()
    print(c.value)
}

Collections

Three Dynamic Containers

All collections are heap-managed with boxed memory handled automatically by the compiler. Indexing starts at 1. Mutation is explicit via .set().

list

Ordered, mixed-type array. Accessed and mutated by numeric position.

let items: list = ["a", 2, 3.0] print(items(1)) items(2).set(99)

index

Key–value store with mixed key types — strings, integers, or floats as keys.

let ix: index = ["k": "v", 2: "x"] print(ix("k")) ix("k").set("new")

dict

Named nested collections. Multi-argument access reaches deep into structure.

let d: dict = {"a" = [1, "hi"]} print(d("a", 2)) d("a", 1).set(99)

Memory Management

Drop Deeply, Drop Cleanly

Rubidium uses explicit memory management through the .drop() method. Calling drop on a variable frees it completely — the identifier ceases to exist.

For collections and strings, .drop() is recursive: every nested box, array key, and allocated value is freed in a single call, eliminating leak paths.

# Scalar drop let x: i32 = 42 x.drop() # x no longer exists # Deep collection drop let data: dict = { "items" = [1, 2, 3], "meta" = ["ok", 99] } data.drop() # frees: dict + both lists # + every value inside them

Error Handling

Try. Handle. Continue.

Unsafe operations go inside a try block. When an error occurs, the error block captures it as a string — accessible directly as error.

try { let result: i32 = 10 / 0 # raises division by zero } error { print("Caught: " + error) # error is a str }

Concurrency

Real Hardware Threads

Rubidium uses actual POSIX threads via the thread module. Functions are dispatched by numeric ID and awaited with thread.wait() before execution continues.

MAIN
fn main() — dispatch threads
THREAD 1
task1() — id: 1
THREAD 2
task2() — id: 2
WAIT
thread.wait(1, 2) — blocks until both return
CONTINUE
execution resumes
use thread fn task1() { print("Task 1 Finished") } fn task2() { print("Task 2 Finished") } fn run_threads() { thread(task1(), 1) thread(task2(), 2) thread.wait(1, 2) }

Xeon Build Manager

One Tool. Every Platform.

Xeon is the official build manager for Rubidium. It initialises projects, compiles source files starting from src/main.rub, and outputs runnable binaries to a build/ directory. Works seamlessly on Windows, Linux, and macOS.

xeon init Creates a new project in the current directory — generates a src/ folder and a boilerplate main.rub entry point.
xeon build Compiles your project starting from src/main.rub. Places the resulting binary inside the build/ directory.
xeon run Builds the project and immediately executes the resulting binary in one continuous step.
Example Workflow — Terminal
$ mkdir my_app && cd my_app
$ xeon init
→ created src/main.rub
→ project ready

# edit src/main.rub

$ xeon build
→ compiled to build/

$ xeon run
→ build + execute

Installation

Get Started in Three Steps

The installer automatically detects and installs required dependencies including Python 3 and Clang. The xeon command is added to your system path automatically.

Windows
01 Download Rubidium from the GitHub repo and rename the extracted folder to exactly Rubidium
02 Place the folder inside the downloaded Xeon directory at rubidium/
03 Run install.bat to install globally
macOS
01 Download Rubidium and Xeon from GitHub
02 Place compiler files inside the Xeon rubidium/ folder
03 Run bash install.sh — configures ~/.xeon and adds xeon to your path
Linux
01 Download Rubidium and Xeon from GitHub
02 Place compiler files inside the Xeon rubidium/ folder
03 Run bash install.sh — auto-installs dependencies and sets up path

To update the compiler, replace the files inside ~/.xeon with the newer version.

Quick Reference

Language at a Glance

No Semicolons

Statements are newline-terminated. Clean, prose-like code structure throughout.

Compile-Time Type Checking

Type mismatches are caught before execution. Assigning a string to an i32 is a compiler error.

1-Based Collection Indexing

All lists and dicts start at index 1, not 0.

println() Overwrites

println() replaces the current line on each call rather than appending — ideal for live output updates.

use vs import

use loads built-in compiler modules. import loads your own external .rub files.

File I/O Built In

file_write() and file_read() are first-class operations — no import required.

No Self in Classes

Inside a class, variables and functions are referenced directly by name — no self or this.

Strict Entry Point

The compiler strictly requires fn main() as the program's execution entry point.
