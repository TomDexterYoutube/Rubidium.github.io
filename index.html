# Rubidium — parallel task example

use thread

let name str = "Rubidium"
let mut count i32 = 0

fn worker() {
    count = count + 1
    print("Task done: ", count)
}

fn main() {
    thread(worker(), 1)
    thread(worker(), 2)
    thread.wait(1)
    thread.wait(2)
    name.drop()  # explicit memory free
}

Core Language

Built for performance,
designed for clarity.

Every design decision in Rubidium balances raw execution speed with developer ergonomics.

{ }

Static Typing

Rigorous compile-time type checking catches mismatches before your code ever runs. No runtime type surprises.

⌀

Manual Memory Control

Use .drop() to explicitly free memory at exactly the right moment. Granular control over your resource lifecycle.

⟳

Hardware Concurrency

Real POSIX hardware threads for true parallel execution. Use thread.wait() for synchronization.

[ ]

Dynamic Collections

Built-in list, index, and dict types with automatic memory boxing handled by the compiler.

▲

LLVM Backend

Compiles directly to highly optimized native machine code. Execution speeds comparable to C or Rust.

⬡

Modular Architecture

Clear separation between internal directives (use) and external file imports (import).

If you have written Python or any C-like language, Rubidium will feel immediately at home.

# Variables — clean, explicit, typed

let name    str  = "Rubidium"
let version f32  = 1.0
let active  bool = True

# Mutable variables need mut keyword
let mut count i32 = 0
count = count + 1

# Explicit memory reclamation — you are in control
name.drop()
# Functions — clear signatures, explicit return types

fn add(a: i32, b: i32) -> i32 {
    return a + b
}

fn greet(name: str) -> str {
    return "Hello, " + name
}

fn main() {
    let result i32 = add(10, 32)
    print(greet("world"), result)
}
# Collections — mixed types, dynamic, compiler-managed

let items list = [1, "two", 3.14, True]

# Mutation via index
items(0).set(99)
print(items(0))  # 99

# Dict type for key-value data
let config dict = {
    "threads": 4,
    "debug":   False
}
# Threading — real POSIX hardware threads

use thread

fn compute(id: i32) {
    print("Worker ", id, " running")
    # ... heavy computation here
}

fn main() {
    thread(compute(1), 1)
    thread(compute(2), 2)
    thread.wait(1)
    thread.wait(2)
}

Xeon Build Manager

One tool.
Every workflow.

Xeon is the official project and build manager for Rubidium — cross-platform, zero-config, and works natively across Windows, Linux, and macOS.

xeon init

Initialize project

Creates a src/ directory and boilerplate main.rub entry point.

xeon build

Compile to binary

Compiles from src/main.rub. Output binary lands in build/.

xeon run

Build + execute

Compiles and immediately runs your project in one continuous step. Fastest feedback loop.

terminal
$ mkdir my_app && cd my_app

$ xeon init
→ Created src/main.rub
→ Project initialized.

$ xeon run
→ Compiling src/main.rub...
→ Build complete (0.34s)
→ Running build/my_app

Installation

Up and running
in minutes.

Xeon automatically detects and installs required dependencies like Python 3 and Clang.

1

Download the compiler

Grab the latest Rubidium compiler from the official repo.

2

Prepare the directory

Place extracted files into the rubidium/ folder inside your Xeon directory. On Windows, rename the folder to exactly Rubidium.

3

Run the installer

Windows: run install.bat
Linux / macOS: run bash install.sh

Xeon is added globally to your system path automatically.
