Why Rubidium

Everything you need,
nothing you don't.

Rubidium is built around a single principle: give the programmer full control without sacrificing safety or ergonomics.

⊕
Static Typing
Compile-time type checking catches mismatches before your code ever runs. Types are annotated with : and checked rigorously.
◈
Manual Memory
Use .drop() to explicitly reclaim heap memory. Collections recursively free all nested data. No GC pauses.
⋈
Hardware Threads
Real POSIX hardware threads for parallel execution. Synchronize with thread.wait() — no async overhead.
▦
Rich Collections
Three distinct collection types — list, index, and dict — each with a clear, consistent access syntax.
◎
LLVM Backend
Compiles directly to highly optimized native machine code via LLVM. Execution speeds comparable to C or Rust.
⊞
Modular Design
Built-in modules via use (thread, random, time, os, FFI). External files via import. Clean, explicit boundaries.
Language Syntax

Familiar. Precise. Expressive.

Rubidium reads like Python but compiles like Rust. Explicit types, explicit ownership, zero ambiguity.

variables.rub Rubidium 
# Type annotation uses a colon before the type
let name:  str  = "Rubidium"
let pi:    f64  = 3.14159
let alive: bool = True

# Type annotation is optional — Rubidium infers it
let score = 42

# 'mut' is required to reassign
let mut count: i32 = 0
count = count + 1

# String interpolation with i""
print(i"Hello from {name}, count is {count}")

# Explicit memory reclamation
name.drop()     # frees heap allocation immediately
functions.rub Rubidium 
# Typed parameters, typed return value
fn add(a: i32, b: i32) -> i32 {
    return a + b
}

# No return value needed
fn greet(name: str) {
    print(i"Hello, {name}!")
}

# Functions create an isolated scope —
# variables inside are NOT in the global pool
fn main() {
    let result: i32 = add(10, 32)
    print(result)      # 42
    greet("world")
}
list.rub Rubidium 
# list — ordered sequence, zero-indexed
# requires 'mut' to modify
let mut items: list = ["hello", 2.5, True]

# Access by index
print(items(0))          # hello

# Mutate an item in place with .set()
items(0).set("changed")
print(items(0))          # changed

# Append a new item with .add()
items().add("new_item")

# Assignments are deep copies —
# modifying 'b' does NOT affect 'a'
let mut a: list = [1, 2, 3]
let mut b = a
b(0).set(999)
print(a)                  # [1, 2, 3]
print(b)                  # [999, 2, 3]
index.rub Rubidium 
# index — flat key→value map
# keys and values can be any type
# uses square brackets with colon separator
let mut my_index: index = [
    "name": "Rubidium",
    1:      "one",
    2.5:    "float key"
]

# Access by key
print(my_index("name"))       # Rubidium

# Mutate a value with .set()
my_index("name").set("updated")

# Add a new key-value pair with .add()
# Errors if the key already exists
my_index().add("new_key", 99)
dict.rub Rubidium 
# dict — each key holds a collection of values
# uses curly braces with = separator
let mut my_dict: dict = {
    "scores" = [10, 20, 30],
    "names"  = ["alice", "bob"]
}

# Access: dict(key, index)
print(my_dict("scores", 1))      # 20

# Mutate a value with .set()
my_dict("scores", 1).set(999)

# Append to an existing key's collection
my_dict("scores").add(40)

# Add a brand-new top-level key (value starts as Null)
my_dict().add("new_key")

# Iterate — yields keys, not values
for key in my_dict {
    print(my_dict(key, 0))
}
threads.rub Rubidium 
use thread

fn task_a() {
    print("Task A on hardware thread")
}

fn task_b() {
    print("Task B on hardware thread")
}

fn run() {
    # thread(fn(), id) — spawns a real POSIX thread
    thread(task_a(), 1)
    thread(task_b(), 2)

    # thread.wait() blocks until all listed IDs finish
    thread.wait(1, 2)

    # Check if a thread is still running
    let still: bool = thread.running(1)
    print(i"Thread 1 still running: {still}")
}
Xeon Build Manager

One tool.
Build, run, ship.

Xeon is the official build manager for Rubidium projects. Initialize, compile, and run your programs with a single command.

xeon init Scaffolds a src/ directory and a main.rub entry point in the current folder
xeon build Compiles your project to native machine code via the LLVM backend
xeon run Compiles and immediately executes your program in one step
install.sh Bash install script for Linux / macOS to set up the Xeon toolchain
install.bat Windows batch install script for setting up the Xeon toolchain
bash — xeon workflow 
$ ./install.sh
✓ Xeon installed to /usr/local/bin/xeon

$ mkdir my-project && cd my-project

$ xeon init

Quick Start

Up and running
in three steps.

From zero to compiled binary in under a minute.

01
Install Xeon
Clone the repo and run install.sh (Linux/macOS) or install.bat (Windows) to put the Xeon build manager on your system.
02
Init a Project
Create a new folder and run xeon init inside it. Xeon generates a src/ directory and a main.rub entry point ready to edit.
03
Build & Run
Use xeon build to compile to a native binary, or xeon run to compile and execute immediately. That's it.
